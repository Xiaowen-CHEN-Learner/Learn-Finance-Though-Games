## Medium severity

### RT-01 — Gambler's Ruin told many winning players they lost money
**Status:** Resolved · PR #5 · `b5f82a9` · `v2/js/modules/gambler.js`

- **Root cause:** after 30 trials the message always said expense ratios had "eaten into your wealth", and the quick-check question began "You just lost money". By exact calculation, 42.8% of players finish 30 trials above their $1M start.
- **Fix:** the end message is chosen from the actual result: up, down, or ruined. The question now asks why the game loses over the long run, without assuming the player lost.
- **Verified:** with forced outcomes, all wins shows the "up … that's luck, not an edge" message, mixed results show "down", and all losses reach ruin at trial 22.

### RT-02 — Reloading after "Skip to content" showed a blank page
**Status:** Resolved · PR #5 · `b5f82a9` · `v2/js/app.js`

- **Root cause:** the skip link leaves `#main` in the URL. On load, any element id in the hash was accepted, and `openTab` hid every panel before checking the tab existed.
- **Fix:** only hashes naming a real tab select one, and `openTab` validates before changing anything.
- **Verified:** loading with `#main` opens Home.

### RT-03 — Progression levels could be earned without demonstrating learning
**Status:** Partly resolved · PR #5 · `b5f82a9` · `bias.js`, `gambler.js`, `v2/index.html`

- **Root cause:**
  - A wrong gambler answer still scored 50.
  - Bias answers could be changed after the explanation revealed the correct one.
  - The trading intro claimed a scoring basis the code didn't use.
  - Growth and SPY award 100 on every visit.
- **Fix:** a wrong gambler answer scores 0. Bias scores the first answer to each question. The trading intro now states that the score is capital preservation.
- **Accepted:** Growth and SPY keep crediting 100 per visit, by owner decision on September 13, 2026. They are informational modules.
- **Verified:** a bias run with Q1 answered wrong and then corrected scores 9/10. A wrong gambler answer records 0.

### RT-04 — Bond column mixed bond series of different duration
**Status:** Resolved · PR #4 · `0b75db1` · `investment_returns.csv`

- **Revised during remediation:** first reported as a copied-forward 2019/2020 value (both 11.87%). The JST Macrohistory Database R6 file itself lists 11.87% for both years. The actual flaw: 1926–2020 used JST's long-duration bond return, while 1960 and 2021–2025 used NYU Stern 10-year returns, and this wasn't documented.
- **Fix:** 1928–2025 rebased to NYU Stern's *US T. Bond (10-year)* series. 1926–1927 stay on JST because Stern starts in 1928, and that seam is documented. 92 values changed.
- **Verified:** only Bond and Gold cells changed. V2 copies and both `market-data.js` bundles regenerated byte-identical. The live CSV shows 2019 = 9.64.
- **Details:** `README.md` §6; `docs/decisions/2026-09-13-bond-gold-resourcing.md`.

### RT-05 — Gold measured annual-average prices, unlike every other column
**Status:** Resolved · PR #4 · `0b75db1` · `README.md` §9, `docs/sources/bond_gold_source_values.csv`

- **Root cause:** the dataset defines each value as $100 held from the start to the end of a year, but gold used annual-average price changes. Also:
  - 1960 was on a year-end basis.
  - 1961 was actually a two-year change.
  - 2026 YTD came from GoldPrice.org, not a first-party source.
- **Fix:** year-end prices throughout. That is the U.S. official price through 1967 ($20.67, then $35.00 from January 31, 1934, per Federal Reserve History), then the last LBMA Gold Price PM fixing of each year. 2026 YTD is now +0.42%.
- **Verified:** source files are hashed (SHA-256) in the README, and per-year inputs are published. The live CSV shows 2025 = 67.41 and 2026 YTD = 0.42.

### RT-06 — Chart.js loaded unpinned, with no integrity check
**Status:** Resolved · PR #5 · `b5f82a9` · `index.html`, `v2/index.html`

- **Root cause:** both versions requested `cdn.jsdelivr.net/npm/chart.js`, which always serves the latest release. A future major version would reach both live sites unreviewed.
- **Fix:** pinned to `chart.js@4.5.1/dist/chart.umd.min.js` with a `sha384` integrity hash and `crossorigin`. That is the same file the unpinned URL was serving.
- **Verified:** charts render in V1 and V2, and the pinned tag is present on both live pages.

### RT-18 — The review read an unpushed branch, not the deployed site
**Status:** Resolved · PR #5 · `efef4cf`, `acb57ca`

  - Hand 10 gave pot odds as 16.7%.

  V2 also lacked the September 11 content sync.
- **Fix:** both waiting commits shipped in PR #5. Future reviews target the deployed commit (see controls).
- **Verified:** the corrected hand 6 explanation is on the live V1 page.

### RT-19 — Gold chart marker sat on the wrong year after the rebase
**Status:** Resolved · PR #4 · `c5a2661`

On a year-end basis the gold revaluation lands in 1934, so the marker moved from 1933 to 1934 in V1 and V2, labeled "Gold Reserve Act revalues gold from $20.67 to $35 per ounce".

### RT-20 — NYU Stern's gold year-end prices mix AM, PM and averaged fixings
**Status:** Resolved · `README.md` §9

Stern's prices matched the LBMA PM fixing in only 45 of 56 years (1970–2025), so gold uses LBMA's own file directly under one documented rule: the last PM fixing of the year.

## Controls going forward

These are recommendations; none is enforced or automated yet.

| Area | Control |
|---|---|
| Process | **Review the deployed commit.** Run `git fetch`, review `origin/main` (what GitHub Pages builds), and state the commit hash in the report. That prevents a repeat of RT-18. |
| Data | **Keep future years on the same rules.** New Bond years come from NYU Stern's 10-year series; new Gold years from the last LBMA Gold Price PM fixing of the year. Record inputs in `docs/sources/bond_gold_source_values.csv`. |
| Data | **Commit the data-bundle generator.** `market-data.js` is generated, but its build script isn't in the repo. A rebuild script reproduced the prior bundle byte-for-byte; committing it would make regeneration reviewable. |
| Dependencies | **Upgrade Chart.js deliberately.** When moving past 4.5.1, change the version and the `integrity` hash together in both `index.html` files, then check every chart renders. |
| Testing | **Script the browser checks.** Verification used ad-hoc headless Edge runs. A repeatable smoke test (tabs, charts, gambler outcomes, scoring) would catch regressions before merge. |
